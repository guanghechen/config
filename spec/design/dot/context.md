# Context 状态与持久化

`dot.context` 保存跨会话的编辑器状态，分为两个文件：

- `editor.json`：theme 与 behavior，所有 workspace 共用。状态变化后经 256 ms 节流保存，写入前与文件比较，相同则不写；
  文件变化时各实例重新加载，多实例之间实时一致。
- `workspace.json`：每个 workspace（git 仓库根）一份，位于
  `<state>/guanghechen/workspaces/<名称>@<路径 md5>/`。保存书签、frecency、搜索与 picker 历史、Explorer 设置和各类开关等
  模块的状态。启动时加载，退出时保存，运行期间实例之间不同步。

## Workspace 多实例保存

同一 workspace 可能同时开着多个实例。保存按字段合并，结果只由“各实例改了什么”和“保存的先后”决定，可预测、可复现。

### 合并单位

- 字段：`workspace.json` 中的 `<模块>.<字段>`，如 `bookmark.pinned`、`frecency.files`、`option.expandtab`。
  `select` 中各 picker 的过滤规则、开关与搜索历史彼此独立，每项设置单独作为字段，如
  `select.find_file.flag_gitignore`、`select.find_file.search_pattern_history`。
- 一个字段要么整体取本实例的值，要么整体保留文件中的值，不做部分合并。

### 规则

1. 基线：加载后对每个字段的规范化值（各模块 `dump()` 的结果）计算指纹，即按 key 排序编码的 JSON 的 md5，只保存指纹。
   保存成功后，基线更新为保存时的指纹。
2. 改动判定：字段的当前指纹与基线不同，即为本实例改过，包括从无到有和清空；改了又改回原值算没改。
3. 保存：
   - 没有字段改过：不读、不写、不加锁。
   - 否则加锁，读取当前文件，用各模块的 `normalize` 规范化文件中的数据；本实例改过的字段取本实例的值，其余字段取文件中
     的值，即使该值为空；原子写入，释放锁。
   - 文件不存在或无法解析：写入本实例的完整状态。
   - 启动时加载失败（某个模块的数据无法加载）的实例退出时不保存：它无从判断哪些字段是自己改的，写回只会用默认值
     覆盖文件；损坏的数据需要手动修复。
4. 锁：`workspace.json.lock`，由 `yoz.fs.lock` 取得 OS 级独占锁（Unix 为 `flock`，Windows 为 `LockFileEx`）。
   - 持有进程退出或崩溃时由系统释放，不存在残留锁。
   - 取锁时创建所在目录，并容忍其他进程同时创建同一目录。
   - 持有者存活时每 10 ms 重试，最多等 2 s；超时后报告并在无锁状态下保存，不丢弃本实例的改动。
   - 取锁失败（等待超时，或锁文件无法打开、加锁）时无锁保存；此时若与另一实例的保存重叠，两次保存退化为整文件
     后写者胜。
5. 可预测性（取得锁的前提下）：
   - 字段的最终值等于最后一个改过它的实例保存时的值；没有实例改过的字段保持文件中的值。
   - 同时退出（如关闭整个 tmux session）由锁串行化，结果等同于按取得锁的先后依次退出。

### 后果

- 两个实例都改过的字段，后保存者覆盖。最常见的是 `frecency.files`（打开文件即改）、`frecency.completions` 与各类
  搜索历史：保留后保存实例的版本，另一实例本次新增的记录丢失。
- `frecency.files` 在排序时清理 30 天前的条目，`frecency.completions` 在排序时删除分数衰减到 0 的条目；只做过查询的
  实例也会因此算作改过这两个字段。
- 书签两边都改时取后保存者的列表，不取并集。
- 运行期间看不到另一实例的改动，下次启动才会读到。
