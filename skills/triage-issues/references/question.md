# `question` 格式

## Item format

| Payload 字段          | 填写语义                                       |
| --------------------- | ---------------------------------------------- |
| `原始问题`            | 来源中的原始问题，保留其语义和范围             |
| `已知 / 证据`         | 与问题直接相关的已知事实、当前观测和证据       |
| `未知`                | 需要澄清的具体事实、意图、约束或假设           |
| `影响 / 收益`         | 未知信息造成的阻塞，以及回答后可推进的工作     |
| `回答依据 / 收敛条件` | 可接受的证据、验证方法，以及足以得出答案的条件 |

## Display body

```markdown
<用一句话说明什么场景触发了疑问、目前已知什么、缺少什么答案，以及未知信息正在阻塞什么；必要时注明来源和原始结论>

- 触发场景：<需要使用该答案的具体任务或决策>
- 已知：<已有事实、当前观测或明确约束>
- 未知：<需要澄清的事实、意图、约束或假设>
- 当前影响：<未知信息阻塞的工作或可能造成的误判>
- 收敛条件：<什么证据或确认足以回答该问题>

### Answer path

<证据充分时给出推荐答案；否则给出验证路径、理由、最小有效范围和收敛条件>

| 澄清项           | 已知         | 未知         | 回答依据 / 收敛条件  |
| ---------------- | ------------ | ------------ | -------------------- |
| <具体事实或约束> | <已验证内容> | <待确认内容> | <可接受的证据或答案> |

<明确不变：回答该问题不直接授权的产品改动或后续工作>

---

- 收益：<澄清未知后的具体价值>
- 代价 / 风险：<验证成本、证据缺口和误判风险>
- Effort / 可逆性：<获取答案的总成本、范围和假设>
- 未决信息：<仍需取得的证据、确认或回答；没有则写“无”>
```

只写已知事实、具体未知、回答依据和收敛条件；不虚构备选方案。

## Actions

- 提供“确认答案 / 先验证 / 转为其他类型 / 延后 / 忽略”，不提供“试做当前项”。
- 确认答案时，将可独立理解的答案写入 `结论 / 决策` 后进入 `answered`。
- 若评审表明核心实为其他类型，经用户确认后转类并保持 `discussing`。若已确认的答案产生新的可执行事项，将原条目设为 `answered`，征得用户同意后再追加新条目。

## Example

示例：配置客户端 timeout 时发现代码默认值为 30 秒，但现有资料无法确认它是产品契约还是可调整的实现默认值；在确认前无法判断能否修改该值，因此为 `question`。
