# `decision` 格式

## Item format

| Payload 字段      | 填写语义                                                      |
| ----------------- | ------------------------------------------------------------- |
| `背景 / 约束`     | 引发决策的背景、已知约束、数据和各选项的依据                  |
| `决策目标 / 影响` | 需要优化的目标、受影响范围和不同选择的主要后果                |
| `原始选项`        | 来源中的完整选项；补充选项标为 `proposed`，缺失时写 `unknown` |

## Display body

```markdown
<用一句话说明什么场景需要做出选择、为什么必须现在选择，以及不同选项会造成什么实际结果；必要时注明来源和原始结论>

- 决策场景：<需要确定方案的具体任务、约束或时间点>
- 必须选择的原因：<不做选择会阻塞什么，或默认选择会带来什么后果>
- 选项影响：<各选项分别会产生的可观察结果、收益和代价>

### Proposal

<推荐选项、理由、最小有效范围、验证方式及处理时机>

| 选项                     | 选择后的结果 | 收益       | 成本 / 风险 | Effort / 可逆性    |
| ------------------------ | ------------ | ---------- | ----------- | ------------------ |
| <原始或 `proposed` 选项> | <可观察结果> | <具体收益> | <具体代价>  | <总成本与回退难度> |

<明确不变：各选项都不影响的 happy path、兼容性或非目标>

---

- 收益：<选择推荐方案后的具体价值>
- 代价 / 风险：<所选方案的成本、副作用和 tradeoff>
- Effort / 可逆性：<各选项的总成本、范围、假设和回退难度>
- 待验证：<尚未确认的约束、选项结果或 tradeoff；没有则写“无”>
```

每个选项都写明结果、收益、成本、风险、Effort 和可逆性；不把补充的 `proposed` 选项写成来源选项。

## Actions

- 提供各原始或 `proposed` 选项、“先验证 / 延后 / 忽略”，不提供“试做当前项”。
- 只有选定方案并将其写入 `结论 / 决策` 后才能进入 `decided`；有后续工作时还需记录处理时机。
- 若后续信息表明核心性质改变，保持 `discussing` 并请用户确认新类型或忽略该项。

## Example

示例：当前实现必须确定 cache 存储方式；内存 cache 延迟低但重启后丢失，磁盘 cache 可持久化但增加 I/O 和清理成本。没有选择就无法确定数据生命周期和实现边界，因此为 `decision`。
